# Technical Specification Portfolio

## オフィスレイアウト管理システム技術仕様書

この技術仕様書群は、中小企業向けマルチフロア対応オフィス座席管理システムの設計・開発において蓄積された技術知見を包括的にまとめたものです。

### 1. [技術アーキテクチャ仕様](./technical_architecture.md)
- **概要**: システム全体のアーキテクチャとテクノロジースタック
- **主要内容**: フレームワークレス設計、ファイルベース永続化、リアルタイム更新基盤
- **技術的価値**: シンプルかつ効率的なWebアプリケーションアーキテクチャの設計手法

### 2. [API設計仕様](./api_design.md)
- **概要**: RESTful API設計とデータ管理
- **主要内容**: 5エンドポイント設計、バージョン管理、自動バックアップ機構
- **技術的価値**: 中小規模システムにおける効率的API設計と楽観的ロック実装

- **主要内容**: ドラッグ&ドロップAPI、DOM操作最適化、状態管理
- **技術的価値**: フレームワークレスでの高機能Webアプリケーション開発手法

### 5. [運用・デプロイメント要件](./deployment_guide.md)
- **概要**: Docker化による運用環境構築と保守手順

- **技術的価値**: 軽量Webアプリケーションの実用的な運用設計

## 🏗️ プロジェクト概要

### システム概要
- **対象規模**: 中小企業（300名以下）
- **主要機能**: マルチフロア座席管理、ドラッグ&ドロップ配置、部署ゾーン管理
- **技術スタック**: Node.js + Express + Vanilla JavaScript + Docker
- **特徴**: フレームワークレス、ファイルベース、軽量実装

### 技術的成果
- **軽量アーキテクチャ**: フレームワークレスによる高速動作と低リソース消費
- **直感的UI**: ネイティブHTML5 Drag & Drop APIによる滑らかな操作感
- **堅牢なデータ管理**: 自動バックアップとバージョン管理による安全性確保
- **運用性**: Docker化による環境統一と簡単デプロイメント

### アーキテクチャ設計思想
1. **シンプリシティ**: 必要最小限の技術スタックで最大の効果
2. **ユーザビリティ**: 直感的な操作による業務効率化
3. **保守性**: 読みやすいコード・明確なアーキテクチャ
4. **実用性**: 実際の業務要件に基づいた機能設計

## 🛠️ 技術選択の背景

### なぜフレームワークレスか
- **学習コスト**: 新しいフレームワークの学習不要
- **パフォーマンス**: 余分なライブラリによるオーバーヘッドなし
- **保守性**: 長期間にわたって変化しない技術基盤
- **理解しやすさ**: ブラウザネイティブAPIの直接活用

### なぜファイルベースか
- **シンプリシティ**: データベースサーバーの運用不要
- **軽量性**: 効率的データ管理の最適解
- **バックアップ**: ファイルコピーでの簡単バックアップ
- **デバッグ**: 人間が読める形式でのデータ確認

### なぜDockerか
- **環境統一**: 開発・本番環境の完全一致
- **デプロイ簡素化**: ワンコマンドでの環境構築
- **依存性管理**: Node.jsバージョン・OS依存性の解決
- **スケーラビリティ**: 将来の複数インスタンス対応
